# Project skills

Project-local copies of the upstream skills live under `.agents/skills/`. They were
copied from the following public repositories; source commit IDs and licenses are
recorded in `.agents/skills/ATTRIBUTION.md` and the included license files.

| Skill | Use |
|---|---|
| `tdd` | Red-green-refactor when implementing behavior and tests. |
| `code-review` | Review an implementation or final change. |
| `codebase-design` | Software/module/API architecture and code structure. |
| `diagnosing-bugs` | Reproduce and investigate a bug or regression. |
| `improve-codebase-architecture` | Periodically survey structure for improvement opportunities. |
| `implement` | Implement an agreed feature or spec. |
| `research` | Research external standards, prior art, or technical questions. |
| `grill-with-docs` | Clarify an ambiguous idea and record agreed domain knowledge. |
| `to-spec` | Turn an agreed plan into an implementation spec and GitHub issue. |
| `to-tickets` | Split a plan or spec into linked implementation issues. |
| `setup-matt-pocock-skills` | Maintain this repo's issue-tracker and domain-doc configuration. |
| `grilling` | Interview the user to resolve decisions; invoked by `grill-with-docs`. |
| `domain-modeling` | Maintain domain terminology and ADRs; invoked by `grill-with-docs` and architecture review. |
| `emil-design-eng` | Primary UI craft, component interaction, motion, and frontend polish guidance. |

For UI work, consult `emil-design-eng` before generic design suggestions. Use
`codebase-design` for software structure; it is not the visual-design authority. Preserve
the upstream skill instructions and review formats. Skills are guidance, not Yeon
protocol specifications.
